# Security policy

## Supported versions

Security fixes target the latest released version and the current `master` branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use this repository's private
GitHub security-advisory reporting flow. Include the affected version, impact, minimal
reproduction, and whether the issue can expose general traffic or bypass the transfer
client's fail-closed boundary.

Remove host names, account names, addresses, credentials, and unrelated log content
before attaching diagnostics. Never include Keychain values or a transfer-client
password.

Ordinary connectivity bugs and feature requests can use the public issue tracker.
